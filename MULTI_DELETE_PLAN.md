## Contract and constraints

- Preserve single-target `path` inputs and add multi-target `paths`. Retire `confirm_path` completely: remove it from the executable tool schema, argument plumbing, and file-tool deletion contract. Do not introduce `confirm_paths`, an ignored legacy argument, or a compatibility shim. Update affected production consumers and scenarios, and propose corresponding documentation changes for explicit approval. This decision concerns the agent-facing file tool; it does not remove actual user confirmation from explorer UI/API behavior or inline-edit review.
- Direct multi-delete produces one selection card in inline-edit mode and executes immediately in normal mode.
- Preserve scripted invocation and Monty single-delete loops without new approval pauses. Approval-policy redesign and Monty suspend/resume are out of scope.
- Preserve full-selection validation, target-change checks, auditing, snapshots, and recovery. Explorer deletion and empty-folder cleanup are existing capabilities.
- Folder deletion is recursive for both single-target `path` and multi-target `paths`: selecting a folder removes it and its contents. Use the shared recorded deletion/recovery path already exercised by explorer deletion, including retained file contents and directory topology. This explicitly changes the current file-tool behavior from empty-directory cleanup to deletion of the selected tree; update affected behavioral expectations against this agreed contract. Root and vault-identity protection remain enforced.
- Normalize and deduplicate targets, then collapse child selections beneath a selected parent folder. For example, `["Archive", "Archive/a.md", "Archive"]` has the effective selection `["Archive"]`. The inline-edit card and result must show that effective selection and clearly identify recursive folder scope. Process each target once; review-time validation must still account for the complete selected tree.

## Open decisions and dependencies

- Input decision (agreed): retain `file_write(operation="delete")`, use `path` for a single target or `paths` for multiple targets, and reject requests supplying both. Remove `confirm_path` completely and do not add `confirm_paths`; repeated agent-supplied targets are not user approval. No separate batch-delete operation is needed.
- Folder decision (agreed): recursively delete selected folders and their contents for both single and multiple targets, using recorded mutations and recovery. Reuse the shared explorer deletion service where its contract fits; do not retain an implicit empty-directory-only mode on the tool's delete operation.
- Overlap decision (agreed): normalize and deduplicate targets, collapse child selections beneath a selected parent folder, and display the effective recursive selection in approval and results. Each target is processed once.
- Failure decision (agreed): preflight the entire request before mutation, reject the whole selection for invalid, missing, protected, or changed targets, and do not silently skip targets. Unexpected execution failures must fail the operation, attempt supported compensation, and explicitly report any partial or uncertain state with recovery information; do not promise filesystem transactionality beyond verified recovery guarantees. Product decisions are settled.
- Implementation integration: share selection preparation between review and execution; retain review-time fingerprints of selected file contents, directory topology, and target kinds in persisted review context. Surface the effective selection in review API/event payloads without changing the provider-native arguments that resume execution. Recheck reviewed deletion scope under the deletion lock at execution, in addition to existing submission-time conflict checks.
- Approval policy is settled: one complete-selection card in inline-edit mode, immediate execution in normal mode, and unchanged scripting behavior. Extend review rendering and stale-target validation without reopening that policy decision. Existing review snapshots cover single-file existence/hash, so directory selection review must account for any contents eligible for deletion.
- Identify persisted review-context or payload changes before implementation.
- Dependency satisfied: shared single-target root protection in [VAULT_ROOT_DELETE_PROTECTION_PLAN.md](VAULT_ROOT_DELETE_PROTECTION_PLAN.md) is implemented, validated, and documented. Native multi-delete must add its own mixed valid-target/root-alias rejection scenario.

## Implementation and verification record

- `file_write` now takes `path` or `paths` for `delete`; `confirm_path` is removed from the executable schema and invocation plumbing, without a compatibility shim. Both single and multiple targets use the shared recursive service in `core/vault_state/path_deletion.py`. Its selection preparation normalizes/deduplicates targets, collapses descendants, validates every requested target and descendant, and fingerprints target kinds, file hashes, and directory topology before mutation.
- Each tool deletion selection gets a separate durable recovery activity with the original task kind, source, label, task ID, and goal/step provenance. This prevents compensation for one failed selection from undoing unrelated earlier work. Explorer requests retain their explicit UI confirmation and existing activity ownership. The shared service attempts retained activity recovery on unexpected execution failure and reports `activity_id` with `recovery_status` (`restored` or `partial_or_uncertain`).
- New review-context data is additive in existing persisted JSON: `file_delete_snapshots` stores per-call fingerprints and the effective target list. Review API/event payloads expose `deletion_targets` separately from unchanged provider-native arguments. Submission checks the complete tree, and execution rechecks the reviewed fingerprint under the deletion lock. Older pending deletion reviews without complete snapshots fail closed and require a fresh review; scripting receives no added approval pause.
- The browser card lists the effective selection and identifies recursive folder scope. Selection targets remain immutable under existing override rules. No new CSS or settings were added.
- Retired the empty-directory-only deletion implementation and its dead result/projection helpers. The updated directory scenario now proves that selected folders are removed recursively and recovered exactly. Updated current executable fixtures to omit `confirm_path`; archived legacy sources remain unchanged.

Existing unsupported directory operations retain their partial-recovery policy. Dedicated deletion activities preserve task attribution; the workflow mutation scenario still asserts the complete mutation count/set and provenance across the task's recovery activities rather than assuming all mutations share one activity.
